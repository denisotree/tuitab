# Выражения

> 🇬🇧 [This page in English](../en/expressions.md) · [← Оглавление документации](README.md)

В tuitab есть небольшой язык выражений, который используется в двух местах:

- **Вычисляемые столбцы** — нажмите `=` и введите выражение, чтобы добавить
  новый столбец.
- **Выбор строк выражением** — нажмите `|`, затем `!=` и выражение, чтобы выбрать
  все строки, где выражение истинно (например, `|!=amount > 1000`).

![Добавление вычисляемого столбца](https://raw.githubusercontent.com/denisotree/tuitab/master/.github/assets/compute.gif)

## Ссылки на столбцы

Пишите имя столбца напрямую. Имена без пробелов и спецсимволов работают как есть:

```text
revenue / units
age * 2
```

Всё остальное — в обратных кавычках: пробел, дефис, скобка:

```text
`к выплате` * 1.2
`цена (нетто)` + `налог`
```

Двойные кавычки для этого не годятся: `"к выплате"` — текстовый литерал, и
арифметика по нему может дать только NULL, поэтому такое выражение отвергается,
а не отвечает столбцом из пустоты.

В поле ввода нажмите `Tab` для автодополнения имён столбцов.

## Литералы

| Вид | Примеры |
|-----|---------|
| Число | `42`, `3.14`, `-5` |
| Отрицание | Ведущий минус — это выражение: `-quantity`, `if(x, a, -b)` |
| Строка | `"Engineering"`, `"N/A"` |
| Дата | `2024-01-31` (`ГГГГ-ММ-ДД`) |

## Операторы

| Категория | Операторы |
|-----------|-----------|
| Арифметика | `+` `-` `*` `/` |
| Сравнение | `==` `!=` `<` `>` `<=` `>=` |
| Принадлежность | `value in (a, b, c)` |

`+` также склеивает строки. Сравнения дают логическое значение — именно его
использует выбор строк `|!=`.

Текстовая колонка остаётся текстом: `concat(sku, "-", size)` сохраняет `007` как есть.
Там, где операции нужно число или дата, текст, который так читается, используется как
число или дата — `sku * 2`, `code == 7`, `year(updated_at)` и `updated_at - 7` работают и
с текстовыми колонками.

```text
salary > 90000
department == "Engineering"
status != "closed"
region in ("North", "South")
contains(name, "^A")
```

Условия объединяются через `and`, `or` и `not`. Слабее всех связывает `or`,
затем `and`, затем `not` — то есть `a and b or c` читается как `(a and b) or c`.
Если нужно иначе, ставьте скобки:

```text
department == "Engineering" and age > 40
department == "HR" or department == "Marketing"
not (status == "closed")
(region == "North" or region == "South") and amount > 1000
```

> Операнд, не являющийся настоящим булевым значением, делает всё выражение
> null, а не молча считается ложью — иначе сломанное сравнение можно было бы
> отрицанием превратить в уверенный ответ.

## Функции

### Строки

| Функция | Результат |
|---------|-----------|
| `concat(a, b, …)` | Объединить значения в одну строку |
| `split(s, delim)` | Первое поле `s` после разбиения по `delim` |
| `substring(s, start, len)` | Подстрока (начало с 0) |
| `len(s)` | Длина строки |
| `contains(s, regex)` | Истина, когда `s` подходит под регулярное выражение |
| `regexp_replace(s, regex, replacement)` | Замена всех совпадений; `$1`, `${name}` или `\1` вставляют группу, `$$` — сам символ `$` |
| `regexp_extract(s, regex)` / `regexp_extract(s, regex, group)` | Первое совпадение или его группа (0 — совпадение целиком); NULL, если совпадений нет |
| `json_get(s, path)` | Значение по пути `path` в JSON-тексте `s`: `$`, затем `.key`, `["key"]` или `[index]`, например `"$.geo.city"`. NULL, если там ничего нет или `s` — не JSON |

Паттерн (и замена) — текст в кавычках, не колонка: он проверяется и компилируется один
раз, когда выражение читается. Флаги — внутри паттерна: `(?i)` — без учёта регистра.

```text
regexp_replace(regexp_replace(message, "[0-9a-f]{8,}", "H"), "[0-9]+", "N")   # шаблон строки лога
regexp_extract(message, "(?i)https?://([A-Za-z0-9.-]+)", 1)                   # хост из URL
json_get(application_client, "$.country_code")                                # поле JSON-колонки
```

`json_get` даёт колонке тип, общий для её значений, — целые, числа, `true`/`false` —
или оставляет текст; значение с ведущим нулём вроде `"00123"` остаётся текстом. JSON-
строка `"42"` и число `42` читаются одинаково — как 42. Для нескольких ключей одной
JSON-колонки операция `expand_json` (`zJ`) разбирает каждую ячейку один раз.

### Математика

| Функция | Результат |
|---------|-----------|
| `abs(x)` | Модуль |
| `round(x)` / `round(x, places)` | Округление, половина — от нуля; `places` — целое от −28 до 28 |
| `floor(x)` / `ceil(x)` | Вниз / вверх до целого |
| `sqrt(x)` `exp(x)` | Квадратный корень, eˣ |
| `ln(x)` `log10(x)` `log(x, base)` | Логарифмы |

Имена и округление — те же, что в `tuitab_calc`. Результат вне области определения
функции — `sqrt(-1)`, `ln(0)` — это NULL, как и значение, которое не число. Результат
всегда дробное число.

```text
round(abs(value - 67184) / 18852, 2)     # z-оценка с двумя знаками
ln(requests + 1)
```

### Даты и время

| Функция | Результат |
|---------|-----------|
| `year(d)` `month(d)` `day(d)` | Части даты |
| `hour(dt)` `minute(dt)` | Части даты-времени |
| `today()` | Текущая дата |
| `now()` | Текущие дата и время |
| `date(s)` | Разобрать значение в дату |
| `date_format(d, fmt)` | Отформатировать дату по шаблону `chrono`/`strftime` |
| `from_epoch(x, unit)` | Целые секунды, миллисекунды, микросекунды или наносекунды с 1970 года (`"s"`, `"ms"`, `"us"`, `"ns"`) как дата-время UTC |
| `time_bucket(dt, width)` | Начало интервала, в который попадает `dt`; `width` — целое число `s`, `m`, `h` или `d`, например `"10m"` или `"1h"` |

`year` … `minute` дают целые. На колонке даты или даты-времени они — как и
`date_format`, `from_epoch`, `time_bucket` — считаются векторно; на тексте разбирают
каждое значение.

```text
hour(Time)                                  # 24 группы для профиля по часам
time_bucket(from_epoch(ts_ms, "ms"), "10m") # десятиминутки
```

**Колонки epoch распознаются при чтении табличного файла.** Целая колонка с именем
времени — `time`, `ts`, `timestamp`, `datetime`, `date`, `epoch` или имя на `_time`,
`_ts`, `_timestamp`, `_at`, — где каждое значение — epoch в одной единице (с, мс, мкс
или нс, годы 2001–2286), показывается как дата-время UTC. В файле остаются целые:
сохранение записывает их обратно, а `t` → Integer их возвращает. В MCP-сервере
`tuitab_inspect` помечает такую колонку, а `"detect_epoch": false` у источника
оставляет целые. JSON, YAML, TOML и markdown не трогаются.

Дата-время с часовым поясом (Parquet, Arrow) показывается, сравнивается и
считается в UTC — момент в фильтре пишите в UTC. Сохранение в Parquet или Arrow
возвращает пояс; `tuitab_inspect` его называет.

### Условия

| Функция | Результат |
|---------|-----------|
| `if(cond, a, b)` | `a`, если `cond` истинно, иначе `b` |

```text
if(salary > 100000, "senior", "standard")
concat(first_name, " ", last_name)
year(hire_date)
```

### Агрегаты по всему столбцу

| Функция | Результат |
|---------|-----------|
| `sum(col)` | Сумма столбца |
| `count(col)` | Число значений |
| `mean(col)` | Среднее |
| `min(col)` / `max(col)` | Минимум / максимум |

Они читают весь столбец, а не строку, — благодаря чему доля от общего это одно
выражение:

```text
amount / sum(amount)     # доля этой строки в таблице
```

> В отборе строк агрегат выносит один вердикт обо всей таблице, а не проверку
> на строку: `|!=mean(age) > 30` истинно либо для всех строк, либо ни для одной.
> Чтобы сравнить строку со средним, поставьте агрегат по одну сторону обычного
> сравнения — `age > mean(age)`.

## Арифметика дат

| Выражение | Смысл |
|-----------|-------|
| `date + n` / `date - n` | Прибавить / вычесть `n` **дней** |
| `date1 - date2` | Число **дней** между датами |
| `datetime + n` / `datetime - n` | Прибавить / вычесть `n` **секунд** |

```text
order_date + 30          # на 30 дней позже
ship_date - order_date   # дней до отгрузки
```

## Приведение типов

Значения приводятся по необходимости — числовые строки становятся числами в
арифметике, логические — `1` / `0`, а `null` проходит сквозь большинство
операций. Тип итогового столбца выводится автоматически (деление даёт дробное,
`year(...)` — целое и т. д.); поправить его можно потом через `t`.

## Примеры

```text
# Вычисляемые столбцы ( = )
revenue / units                         # цена за единицу
concat(city, ", ", country)             # совмещённая метка
if(score >= 60, "pass", "fail")         # корзина
year(created_at)                        # извлечь год

# Выбор строк ( | затем выражение )
|!=amount > 1000                        # крупные строки
|!=department == "Sales"                # один отдел
|!=region in ("North", "South")         # набор регионов
```

После выбора строк выражением совпавшие строки **выделяются** (не скрываются).
Превратите их в отдельный лист через `"`, удалите остальные через `d` или
скопируйте через `yr`.
